# Lamp runs

The one list of every merged row and fix that now waits only for a run on a real lamp, each given a lamp and a builder. It follows the lead's decision of 21 Oct 07:3x on #1711: real-lamp runs are spread over the builders who have a lamp and a person, and build moves only when rows are tried. A code issue closes when its PR merges. Its lamp run lives here, not in a new issue.

**How to use it:** book your lamp with its person, run the row on the build named, and post the result on the row's PR. The first builder then strikes the row here. A row that moves the body needs the person at the arm. **Needs** names only what the office Mac can't do (the lead, 22 Oct 07:2x on #1711). **Mac** means the Mac does it: its speaker (played lines, two `say` voices), its camera, or a screen face (a photo or video of a made-up person on its screen), as the lead set on 21 Oct 13:1x. **Test input** means an input already proven by hand is given by a test hook ("A physical input by a test input", below). **Hand** means a real hand must touch the lamp, because the row tests the input itself. **Real person** means only a person will do: at the arm while the body moves, their own yes, keys or account, or their own voice where a played one can't stand in. **Nothing** means the lamp needs neither. Anything else (the app, the office busy, the Wi-Fi cut, the relay blocked) is a condition or equipment, not a person. A row that counts something over "an hour" runs 15 minutes and is extrapolated, unless what it counts happens less than about 4 times an hour; then it runs the hour and says so on the row (the lead, 22 Oct on #1711).

**Before every run, a preflight** (the lead, 22 Oct 07:3x on #1711), so a run isn't spent on a switch left off. Check each item, and run only when all of them hold:
1. **The build:** the lamp's running build has the row's PR, by the running binary's hash against the build's `SHA256SUMS`, or by its version.
2. **The switches:** every switch the row names is on in the running units' environment. Read the names only (`systemctl show <unit> -p Environment`), never a key file.
3. **The parts:** every part the row needs is active.
4. **The head:** it faces what the row needs: the screen for a screen face, the person for a person.
5. **The Mac:** its speaker level, its camera feed and any test input the row uses are ready.
6. **The lamp is yours:** nobody else holds it, by the lock or the Queue.

A run that skips the preflight and finds a switch off isn't a result. Post it as "not run", with the item that failed.

**Build** is the branch the switch is on: `#1712` for the voice (the second route), `lamp-voice` for every other part.

**As of** `lamp-voice` `4c733283b` and #1712 `0f92dd0ff` (21 Oct, 12:5x +07), with the merges up to 12:5x and the runs up to 22 Oct 15:37 struck or noted. A row's owner says on #1722 when a run is done, and the first builder strikes it here. The sources are every `until` row of `switches.md` on both branches, `build-rows.md` (the 20 Oct 18:28 copy), the morning list of 21 Oct and the open PRs.

**A physical input by a test input** (the lead, 22 Oct 05:5x on #2602): an input already proven by hand once, namely the privacy slide (Fifth flipped it on lamp-52e6 on 20 Oct, and the microphones closed) and the head pads (#1362, a real touch on lamp-52e6), needs no hand again. A row that only tests what the software does *after* the input runs with the input given by a test input. The input is a test hook, off in every product unit, and the row's result names it. A row that changes how the switch itself is read (the pin, the chip, the controls worker's reading) still gets one real flip. Freed this way:

- `LAMP_SKILL_ROUTINES` and `LAMP_REST_REQUESTS` (lamp-06c1, Jarvis): the privacy step of each.
- Guard mode (lamp-06c1, Jarvis): "with privacy closed it texts".
- `LAMP_LIGHT_WHILE_MUTED` (lamp-0c89, Mobile): the app's light row with the switch closed.
- `LAMP_PRIVACY_GAP_RIDE` (lamp-75c9, Eighth for Third): its talk hour, with the gaps given by the input.
- The head pads, after the touch (lamp-c0a4, Thirteen): `LAMP_HEAD_TAP_CUE_DBFS` (the hum's level, by ear, after a tap), `lamp-voice --controls-mute` (a tap opens a crash's mute), `LAMP_RING_ASLEEP` (sleep by a held touch, tap to wake), `LAMP_STOP_TOLD` (a head stop, then the next request is told), `LAMP_CONTROLS_WAIT` (a press or touch still stops at once), `LAMP_REMINDER_PULSE` (a hand on the head shows no pulse), and #2668's stretch yielding to a hand.

Still a real flip or touch, because they change how the input itself is read: `LAMP_PRIVACY_CONTROLS` on lamp-52e6 (the controls worker's own reading of the slide), `LAMP_PRIVACY_CONTROLS=no-slide` (a lamp with no slide), #1362's head touch in the product units (lines 97 and 98 read as touch, stroke and sleep), and the factory step that finds a unit's pads (#2208 item 4). The test inputs themselves are Eighth's (#2602, 22 Oct 05:5x): until they are merged, these rows wait for them, not for a hand. Both have been shown on a lamp: on lamp-52e6 on 22 Oct 06:14 (Fifth, #2602 06:2x, with #2752 stacked on #2750), the privacy file closed the voice's eyes in 22 ms and a held touch slept the lamp, which a tap woke; on lamp-75c9 at 06:39 (Nine, #694), the room microphone stopped within one level period of a close. Fifth's run also found what to look at next: no red ring on the close, and no chime or ring change on sleep.
