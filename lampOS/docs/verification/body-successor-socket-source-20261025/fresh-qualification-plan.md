# Separate candidate qualification after the binding finding

Original commands and the full binding limitation are preserved at
`first-commands-unqualified/`. Their successful outcomes do not establish
execution of the candidate library. No old observation is renamed.

The next allocation runs only the candidate in a dedicated initially absent
compiler target directory. Existing registry sources may be read; no compiled
artifact is imported from the prior shared target. Exact candidate source
and current public base are checked before launch, then held unchanged.

Fixed sequence: formatting, strict all-target Body Clippy, complete Body
no-run compilation with JSON metadata, exactly one direct ownership case,
then exactly one complete Body run with default test parallelism. The
baseline and ownership-negative observations are not repeated. Compiler
preparation failure is distinguished from a test result; every outcome
is retained, with no retry-until-green. No workspace build or local ARM64
execution is included.

A private Cargo target-runner wrapper copies and hashes each actual
Cargo-launched test executable immediately before replacing itself with
that same executable and arguments, in the same working directory and
inherited environment. Wrapper configuration/stage variables and its own
hash are recorded. Compiler JSON, byte witnesses and source guards bind
the resulting epoch. This explicitly changes the launch instrumentation;
it is no isolation, timing or hardware claim. Fixture-spawned children are
not individually wrapped; complete owned process-group closure is checked.
Zero-case doctests do not supply a test-executable wrapper receipt.

Two compiler jobs only in the next coordinated slot; at least 5 GiB free
before each build or witness copy. The original slot was released to
Cloud; this plan is UNRUN until a new allocation. No runtime/deadline change.
