# #2809 saved-state audit: remaining lampOS crates

Read-only code audit on 2026-10-23 against public integration base `3e75cc3cb`. The separate #3269 Update repair is not treated as landed by this inventory. Paths below are relative to `lampOS/`. No Cargo, old binaries, device commands, or GitHub posts were run. Owners below are component ownership recommendations, not claims about an assigned individual.

Scope: all crates other than Schedule, Tasks, Records, Memory, Skills, Setup (separate audit) and Update (companion inventory). Shared readers in the remaining crates are included. Searched persisted paths, filesystem reads/writes, deserializers, schema/version checks, fixture directories and named compatibility tests. Runtime bus state, sockets, locks and host `/proc`/`sys` reads are distinguished from flash stores.

**Evidence distinction:** “forward test” below means a current reader receives authored future-shaped data. “back fixture” means a current reader consumes frozen older bytes. Neither means a previous release's reader executable was built/run on current output. No actual previous-reader execution was found in the inspected compatibility tests. `/var/lib` fixtures exercise the same bytes that survive a reboot; that is not a measured reboot. `/run` files do not survive device reboot.

## Qualification gaps to carry into #2809

1. Actual previous-reader execution is missing across this audited group. Frozen old bytes → today's reader proves upgrade compatibility only. A rollback qualification needs chosen previous release binaries reading the new writer's output (plus returning to current reader), separately from process restart/reboot claims.
2. Preserve named exceptions: Body poses/moves stay strict for mechanical bounds; mute/privacy fail closed; photo-unconfirmed retention intentionally deletes unreadable records; optional Settings/Surround future tests are expected failures. Do not turn these into blanket lenient JSON without contract review.
3. Narrow newly discovered state candidates: Body first-stand future Outcome resets record, Voice privacy checkpoint strict future handling, generated/app skills indices fallback to empty, Actions caps lacks dated old state fixture.
