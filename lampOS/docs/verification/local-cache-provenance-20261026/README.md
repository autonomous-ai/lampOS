# Historical local startup cache provenance audit

Read-only audit of retained controllers, snapshots, compiler receipts, preserved executables and current depfiles. No Cargo invocation, source edit, device operation or public action. `observations.json` contains the detailed evidence; filesystem times are observations, not an authenticated execution history.

## Findings

- The shared target was born at 03:10:43 UTC. Review controllers explicitly reused it: #3543 completed 05:37:46, #3544 05:56:21, #3548 06:52:10. The startup worktree's Cargo.toml was born at 08:01:43, before startup control identity 08:10:42 and full-gate identity 08:14:46. This is positive evidence of target reuse, not an isolated cold gate.
- The first control preserves the expected disabled-allowance failure and restored transport result, with source restoration. Its commands use quiet Cargo and retain no complete compiler JSON/dependency graph. These fixtures demonstrate their observed behavior but do not independently certify every transitive cached library's source.
- Original 1ec full compile was deliberately interrupted at 08:22:58, before full runtime tests. Its receipt retains exit -15 and source guards; never label it a completed full gate. It emitted 106 local compiler-artifact rows: 103 nonfresh, 3 fresh, including 14 nonfresh Voice rows. Its 37 non-executable local rows had 3 fresh.
- Completed 1cad compile emitted 139 local rows: 94 nonfresh, 45 fresh; all 15 Voice rows were nonfresh. Of 37 non-executable local rows, 33 were fresh. **Thirty of those 33 have identical output filenames to nonfresh rows emitted by the preceding 1ec compilation. All 33 owning package snapshots match byte hashes and modes between frozen 1ec and 1cad.** The three already-fresh rows in both are camera's build script, vendored sonora, and voice-processes. This supports ordinary reuse within the startup worktree, substantially narrowing the earlier-worktree concern. It does not reconstruct historical transitive linking or authenticate artifact bytes at the earlier compile boundary.
- All **102 preserved executable copies** still match their recorded hashes. **99 current target executable paths** still match; the three replaced paths are update's library-test executable, install test, and updater binary. Historical final-artifact guards were retained. Subsequent replacement is not evidence that those old runs executed the replacement.
- Current depfiles contain three old-review-root entries: two Expression `it` variants from #3548 and one Voice library-test variant from #3544. **None of those three stems occurs in the 102 bound startup executables.** They are orphan variants relative to this bound set, not proof that the startup gate selected them.
- Current depfiles reference the startup root in 51 files. Direct `.d` siblings are available for 86 of the 102 executable paths. Their discoverable relative source references have no current hash mismatch against the frozen 1cad snapshot. Depfiles often use relative paths; old-root absence is therefore not proof of origin. Current depfiles can have been overwritten since the run.

## Limits and recommendation

Retain the historical pass/fail counts, mutant detection, source snapshots, and executable hashes as observed evidence. Narrow any stronger claim that this proves every transitive local library was compiled from the named worktree: no empty-target assertion, full frozen depfile set, or hashed transitive compiler graph was retained. Do not infer contamination merely from orphan variants, and do not infer complete cache correctness merely from newly compiled Voice tests.

For the next local qualification, use a target directory atomically created for that frozen worktree and assert absence before creation. Retain the ownership/controller timestamp, source snapshot, compiler JSON, depfile paths and hashes for every local library/build script/executable, then hash the actual tested executable copies and final source. Reuse only within that explicitly owned target; if a reuse is intentional, retain and compare the previous complete provenance boundary. A unique target name plus birth after the controller and initial registry compilation is useful corroboration, but weaker than an explicit absence/ownership assertion; this applies to the newer #3570/#3574 reports without declaring their results invalid.

Original native CI audits remain separately qualified by original event, exact checkout/preview parents, tree equality and test census. This local-cache uncertainty neither erases those native results nor turns a local host pass into physical-lamp acceptance.

## Publication normalization

`<scratch>/` denotes the local temporary evidence/worktree root; the retained relative directory and file names identify each separate source, target, controller and receipt. `<cargo-bin>/` denotes the local Cargo executable directory. These aliases replace only absolute machine-specific path prefixes, including JSON object keys and command arguments. All other values, source/artifact hashes, timestamps, counts and findings are preserved. The implementation script is not part of this publication. `SHA256SUMS` binds these normalized publication files, not the private originals.
