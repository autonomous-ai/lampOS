# What is taken from V1, and what is not

Written 2026-10-14. V1 of the lamp's software is the Go server (`system/`)
and the Python hardware runtime (`hal/`) in this repository. V2 was started
over because parts of V1 were not well enough designed or built, so V1 is
not the reference: each of its components gets a verdict before anything
is carried across. The owner's instruction, 2026-10-13: "evaluate all v1
components and decide if you want to reuse/reimplement/borrow the concept
and rebuild it/ignore it".

## Where this comes from, and how far to trust it

- An audit of V1 made on 2026-10-13: 205 fact sheets, one for each
  component, each with what it does, where, its tests, and the evidence in
  its code and history of trouble or of care. The audit is kept outside
  the repository; the sheet ids below (`GO-2.5`, `HAL-3.10`) are its.
- The verdicts were drafted on 2026-10-14 by a second reader working from
  those sheets and from the V2 documents in this directory, one row for
  every sheet, none skipped.
- The builder then checked: the twenty things to carry over and the
  fifteen lessons (sections 2 and 3), read in full; four of their figures
  against the sheets (the face-size measurement in HAL-3.13, the fast and
  slow cores in HAL-5.18, the voiced-share note in HAL-1.10, the facing
  vote and its two warnings in HAL-3.10), all four as the sheets have
  them; every `reuse as is` and `needs a look` row; and fourteen of the 92
  `ignore` rows chosen at random. **The other rows have not been checked
  one by one against their sheets.** Treat each as a considered first
  judgement, and read the sheet before acting on it.
- The Jev figures (54 of 63 commands right and none wrong, 98 of 99
  non-commands left alone, 0.73 s a decision) are V2's own measurement of
  2026-10-14 with V1's client and V1's 162 labelled cases
  ([policy.md](policy.md)).

## How to read it

- **Verdict** is one of: `reuse as is` (data that can be used unchanged:
  tables, recordings, test cases, hardware facts), `rebuild from the idea`
  (the concept is right, the implementation is not carried over), `take
  the cases` (the behaviour is not carried over, its tests or measured
  numbers are), `ignore` (not wanted in V2, with the reason), `later`
  (wanted, in the last stage: setup, Wi-Fi, updates, the operator's
  pages), `needs a look` (the sheet does not settle it).
- **State in V2** starts with `built`, `partly`, `planned` or `none`.
  "built (another way)" means V2 covers the job by a different design.
- Quotation marks hold words taken from a sheet or from the V1 or V2
  document it names. Numbers are the sheets' unless a V2 document is named.
- Part names are V2's plain ones: Voice, Body, Eyes, Actions, Tasks,
  Memory, Policy, Controls, Schedules, Expression, the bus, the ring's
  owner, the surround (setup, network, updates, reset, the operator's
  pages), and the second speech route.
- [actions.md](actions.md) leaves four things "Not yet judged": the
  scenes, following, music and "stop talking". This page proposes a verdict
  for each (HAL-4.20 and HAL-4.21, HAL-3.14, HAL-2.17, and the speech
  cancel in GO-1.6).

## 3. What V1 got wrong that V2 must not repeat

1. **HAL-5.15, HAL-5.14.** One process owned all hardware and shared its state through 86 module-level names that 117 files import: each V2 part owns its own state and the others ask for it.
2. **GO-2.22.** Every sense and message went through one 1,433-line handler that turned it into a tagged sentence for a language model (269 commits, 62 fixes): what is sensed goes onto typed topics, and what must be decided is decided in code.
3. **GO-1.5, HAL-1.20, EXT.12.** The model moved the lamp by writing text tags into its answer, and wrote them inside a shell `echo` too: an action is a call with a result, never text to be found in speech.
4. **HAL-3.1.** Sound sensing was hung on the camera's frame tick, so switching the camera off stopped the lamp noticing sound: no sense may depend on another sense's loop.
5. **GO-1.1, EXT.1.** A 79-method interface let about 15 methods be silent stubs that nobody noticed until "skills went stale": keep interfaces small, and say plainly what is not offered.
6. **HAL-4.24.** The reflex that stops the body when the agent link drops was wired into five back ends and missing from the lamp's default one: a safety rule lives at the hardware's owner and lapses by itself.
7. **HAL-4.14, HAL-4.15, HAL-4.21.** Normalised joint values were treated as degrees in the speed limit and the tip-over check, and two named directions are "known to be wrong": use one unit from the encoder to the limit, and convert in one place.
8. **GO-3.5.** An update was checked only once a lamp had been given a key, and the updater script itself was fetched and run after a syntax check: an update is signed from the first build or it is not an update.
9. **GO-2.17, GO-1.8, GO-3.1, HAL-5.14.** The LLM key doubled as the admin credential and the hardware token, a default admin password was the hardware id's suffix, and passwords were logged: one credential for one purpose, and none in a log.
10. **HAL-5.19, EXT.33, and the audit's repository facts.** CI ran 132 of 3,143 Python tests, the full suite "is not claimed green", and of latency "Nothing here is measured yet": every test runs on every push, and a claim carries its measurement.
11. **HAL-1.17, EXT.16, HAL-3.17, GO-1.16.** Behaviour was written as prose for a model (a 36 KB prompt, thresholds in a skill, statistics by `ls` and `cat`, a sentence as the only barrier against repeating a task) and nobody counted how often the model obeyed: what must hold is code, and what is left to the model is counted on the lamp.
12. **HAL-5.3, HAL-4.8.** Nothing owned the light or the body, so precedence was an if-chain repeated in each route and four hold mechanisms each needed a backstop for a holder that forgot: one owner arbitrates, and a request that is not renewed lapses.
13. **EXT.3, GO-2.6, EXT.10.** Six back ends were copies kept in step by hand, and the Jev client existed twice with different thresholds and no reason given: one definition, shared.
14. **HAL-2.16, GO-1.13, EXT.4.** Liveliness ran on timers (a spoken "Uhm" that could hardly fire, mumbling that was switched off, a heartbeat that "messaged the owner ... every 30 minutes"): the lamp reacts to something that happened, or does nothing.
15. **GO-2.18, HAL-5.16, GO-1.10.** Settings were one file written in place by one process and read at import by another, beside 437 environment variables, so changing a setting restarted the hardware: one writer, whole files, read at start, and no restart while someone is speaking.

## The owner's scope decisions, 2026-10-19

On 19 Oct, between 07:1x and 07:3x, the owner went through every V1 capability that was deferred, dropped or waiting for a verdict, one at a time. The question for each was whether it fits V2's direction. Their rule (verbatim): "we don't wna totblindly move v1 features to v2. it must make sense. it must fit with v2 product philosophy. v1 was not perfect." While answering, they set how each one is built: "think in terms of skills all the time. that's the modular architecture design we do with skills, topics, and actions", and "we should have core skills and installable skills. but we should try to build everything as skills. core skills like core apple apps right always installed on the phone and then installable skills like installable apps".

No lamp has shipped. V2 is installed on the current lamps before they ship, so nothing migrates from V1, and updates must carry a shipped lamp to V3, V4 and V5 in place ("1 is gone. but we need to build it in a way that v3 v4 v5 will be updated fine").

**Kinds of decision:**
- **Core skill:** always installed.
- **Installable skill:** the person chooses it.
- **System:** built in, below the skills.
- **Not in V2.**
- **Deferred.**
