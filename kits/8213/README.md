# Split ROW kit: #8156 + #8213 on one lamp, in two pieces

One lamp ROW for #8156 (head `9abee5c4ef13ff5439a459bfe8f51bb1182061e5`) and #8213 (head `11bc59c692`), split into two pieces of about 15 min each. The default lamp is `lamp-ee17`. Set `LAMP=` to use another.

- **Piece A** takes the lamp from stable to the PR build (SEQ1) by a real round and runs #8156's legs 3-6. It does not run r2. It ends with the lamp on SEQ1 and writes `PIECE A END: lamp on SEQ1, piece B must run next on this lamp` to `logs/pieceA/times.log`.
- **Piece B** runs on the same lamp, right after A. It runs #8213's Hermes legs 6-8, then r2 back to stable's own binaries (as SEQ2), then the put-back, the as-found compare and the two ROW drafts.

The kit is self-contained. Every path is relative to this folder. Every outside input is an env var (see below). The kit holds no password, key or host name: the runner's `LAMP_SSH` handles auth. Nothing is posted anywhere. The kit reads GitHub (`gh api`, `gh release view`, `curl` of the stable feed) and writes two draft files for a person to post.

The kit was first written and run on lamp-c0a4 (the #8156 round kit and the #8213 legs). This folder is a copy; the originals are unchanged.

## What the runner provides

| Env | What |
|---|---|
| `LAMP` | the lamp id, default `lamp-ee17` |
| `LAMP_SSH` | **the runner's own** ssh stand-in, never the kit's. `$LAMP_SSH "<command>"` must run `<command>` on the lamp as its login user (`orangepi`), pass the kit's stdin through, and allow `sudo -n` (passwordless, or the stand-in arranges it without eating stdin). The kit sends root scripts as `$LAMP_SSH "sudo -n sh -s"` with the script on stdin, and copies files as `tar ... \| $LAMP_SSH "... tar -xf - -C /tmp/t8156"`. |
| `LL` | the lamp lock script, called as `$LL <lamp> try\|renew\|release\|status <who> <session> [for]`, exit 0 = ok (e.g. the team's `lamp-lock.sh`). It is called with `LAMP_SSH` unset, because `lamp-lock.sh` reads `LAMP_SSH` as its own ssh command. `LOCK_WHO` / `LOCK_SESSION` default to `row-kit` / `split-row`. |
| `CLIPS` | a folder of rendered WAVs, `<ID>.wav` for the IDs in `clips.txt` (T1-T4 for A; HMAKE, HTRY, HRUN, HDEL, YES for B). ElevenLabs only, rendered before the slot. The wavs are not in the kit. |
| `EXPECT_STABLE` | the stable sequence the build was made on. No default: the build is rebuilt on the new stable's commit. |
| `LOCAL_ART`, `TREE`, `MERGE`, `GITDIR` | the local full ARM64 build folder, its tree sha, the merge commit built (the PR heads merged into lamp-voice), and a git checkout holding `MERGE`. No defaults. |
| `HOSTU` | a host build of `lamp-update` from `MERGE`, for prep only (see the TODO below). |
| `WANT_SHA_AGENT_NS` | optional: the sha256 of the agent-ns text the build writes (see the TODO below). With it, the read-back is exact. Without it, the read-back is a content check: what the round wrote carries lamp-update's mark in its first 512 bytes and #8213's `/run/lampos-skill-start` line(s), and its sha is recorded and compared at AS FOUND. |
| `LAMP_HARNESS` | only if the lamp keeps a Harness newer than the build's pin (a round never moves Harness down) |
| `LOGROOT` | optional, default `./logs`. **A and B must use the same one**: B reads A's as-found record from it. |

## RUN

```sh
cd kit
export LAMP=lamp-ee17 LAMP_SSH=<your stand-in> LL=<your lock script> CLIPS=<wav folder> \
       EXPECT_STABLE=<stable seq> LOCAL_ART=<build folder> TREE=<tree sha> MERGE=<merge sha> GITDIR=<checkout> \
       HOSTU=<host lamp-update> [WANT_SHA_AGENT_NS=<sha256>]
# 0. Mac only, once per build (touches no lamp): the two signed local channels in ./out (and a throwaway key in ./secret)
HEAD_SHA=<full sha of the PR head that is a direct parent of MERGE> HARNESS_WANT=<the build's Harness pin> zsh prep-local.zsh
# 1. piece A (lamp lock taken and released by the piece)
zsh pieceA.zsh
# 2. piece B, right after A, same lamp, same LOGROOT
zsh pieceB.zsh
# If A stopped after r1 (its log says so) and B's legs are not wanted: put the lamp back only
zsh pieceB.zsh finish
```

`HEAD_SHA` for prep: `prep-local.zsh` checks that `HEAD_SHA` is a **direct** parent of `MERGE`. In the 22 Nov build (merge `c98fd771d0`, "stable 15543 + #8156 + #8213"), the parents are lamp-voice `e1f55d813a` and #8213's `11bc59c69276b73a417549ca55126f3b34e456d3`; #8156's head is under #8213's. So pass #8213's full head, not #8156's. Recheck this for the rebuilt merge.

## Order and what each step checks

**Piece A**: lock, as-found record, pre0, stable0, pre, copy, stage, r1 (+ExecStart check), verify, readback, ready, near_on, unmute, legs 3-6, then the put-back: engine as found, engine file as found, `/tmp/sd8156` gone, near_off, remute, nostop, release.

**Piece B**: lock, seq1 check, ready, near_on, unmute, legs 6-8, r2, near_off, remute, putback, engine file, read twice, as-found compare, rounds, drafts, release. `finish` mode runs: lock, r2, near_off, putback, engine file, read, as-found compare, rounds, drafts, release.

| Step | PASS when (otherwise a STOP, and the piece's put-back runs) |
|---|---|
| as-found (A) | a read of the build, the engine choice and its file (bytes), the kept engine, the sha256 of agent-ns, `/usr/local/bin/hermes` and lamp-update, every drop-in, lamp-update's non-/run drop-ins by sha (e.g. `/etc/.../zz-cdn-feed.conf` after #8302), and lamp-update's loaded ExecStart argv. The engine found (OpenClaw or Hermes) is what every put-back restores. Any other engine is a STOP. |
| pre0 | the live stable feed says `STABLE_SEQ` (= `EXPECT_STABLE`) |
| stable0 | an ordinary stable round, only if the lamp is not on stable yet |
| pre | on stable, product line, no drop-ins, nothing staged, Harness as wanted |
| r1 | `ROUND 1 DONE` and `switched to\|up to date: build SEQ1`, **and** the ExecStart systemd loaded names `--channel-url file:///var/lib/lampos-t8156/ch1/` (the kit's `/run` `zz-t8156.conf` sorts after `zz-cdn-feed.conf`), and r1's log has `url=file:///…/ch1/`. Otherwise: STOP. |
| verify | `VERIFY PASS`: SEQ1, the PR's lamp-update and lamp-tasks running, Harness as wanted |
| readback (A) | by sha against the build's own: `READBACK agent-ns PASS` (= `WANT_SHA_AGENT_NS`); `READBACK one-path-hermes PASS` (`/usr/local/bin/hermes` = `git show $MERGE:lampOS/crates/update/src/agent_ns/wrapper/one-path-hermes.sh`, the text a test pins); `READBACK hermes-launcher PASS` (the same file, carrying `HERMES_NONINTERACTIVE=1`). Any FAIL: STOP before the legs. |
| near_on | `NEAR OFF SET`: its own drop-in `/run/systemd/system/lamp-voice.service.d/zz-sd-split-near.conf` with `Environment=LAMP_NAME_NEAR=off` (the product unit says `=on`), one lamp-voice restart, the running env read back `off`. It is logged, written on the row lines, and removed in that piece's put-back (`NEAR REMOVED`). |
| unmute / remute | the privacy mute lifted in software for the ROW and put back as recorded |
| legs 3-6 (A, `legs8156.zsh FROM=3 UNTIL=6`) | READY (the kept Hermes is live within 120 s, its pane idle, the 3 `HERMES_*=1` names in its env), ENGINE, TELEMETRY, YOLO_ONLY_KEPT, ONE_AGENT; T1 (sea.md, work done within 420 s), T2 (+1 line in the same session, T3 played while it runs), T4 (fruits.md); ONE HARNESS (one agent for T1, T2, T4, with no new pane, rotation or replacement). Its put-back sets the engine back to the one found, once. A leg STOP or a non-zero exit stops piece A. |
| seq1 (B) | the lamp is on SEQ1 and `VERIFY PASS` (no wait). Otherwise STOP, and nothing is touched. |
| legs 6-8 (B, `legs8213.zsh FROM=6 UNTIL=8`) | agent-first drop-in on; ENGINE hermes; MAKE_hermes (`make: handed to hermes in the lamp's kept session`, `made by the agent (Hermes)`, `new=0 reply>=1 close=0`, the same kept agent, no make-/skill- pane; DeepSeek = VOID); TRY_hermes and RUN_hermes per run (one `its own pane, not the skill-start door: … no exact exec allow-list` line, a `harness new`, the run's token file seen, no launcher claim, `do.task: handed to lamp-tasks`, lamp-one-hermes kept); REMOVE (`removed by voice`). Its put-back: the engine as found, agent-first off, the ROW files removed, `/tmp/sd8213` gone. |
| r2 | `switched to\|up to date: build SEQ2`: stable came back as **stable's own binaries served at SEQ2, above SEQ1**, because a round never installs a lower sequence. |
| putback | `PUTBACK OK`: the kit's `/run` drop-ins and channels removed, lamp-update restarted on its product line, the real feed's answer `build STABLE is older than build SEQ2` |
| engine file | `engine-default.json` back to its bytes found at A's start (`#8156`'s `engine` verb writes its own; removed if it was absent) |
| AS FOUND | `AS FOUND PASS` when the engine and its file, agent-ns, hermes, lamp-update (by sha), every drop-in, the non-/run lamp-update drop-ins (by sha), the loaded ExecStart and the kit's leftovers all match the start. The build sequence is noted, not failed, when it went stable → SEQ2 (or older-than-stable → stable0 → SEQ2): the kit cannot go back below a sequence. Anything else: `AS FOUND FAIL <what differs>`. The put-back leaves, by design, `/home/orangepi/t8156` (the round's evidence and mute record) and its own lines in `/home/orangepi/changes.txt`. |
| ROUNDS | `ROUNDS n`: the lamp's own updater's serve starts on the test channel in r1's and r2's logs (each rounds at its start). 4 is expected: r1 self-switch + new updater, r2 the same. |
| drafts | `logs/row8156-draft.md` and `logs/row8213-draft.md`, each starting `ROW #<pr> <head> on <lamp> build <SEQ1>: PASS\|FAIL (LAMP_NAME_NEAR=off)`, with its verdict and journal lines fenced. **Posted by nobody.** |

The pieces' traps (EXIT/INT/TERM) run each put-back once, whatever stops. Every put-back step has its own done flag, and the normal end and the trap call the same function.

- **A's trap** puts back the engine as found, the engine file, the temp dir, near_off, remute and nostop, then releases the lock. It never runs r2. After r1 it logs that piece B (or `pieceB.zsh finish`) must run next.
- **B's trap** first cleans up anything left by a cut legs run, then runs r2 if r1 was done and r2 not yet, then putback, the engine file, near_off and remute. It then runs the as-found compare and the drafts, and releases the lock.

## Times (last real run of the round kit; Hermes legs at their caps)

The last real round run (21 Nov, lamp-c0a4) took about 5.5 min from lock to ready, and about 5 min from r2 to release.

| | typical | worst case (caps as they are) |
|---|---|---|
| Piece A | **~15 min**: round 5.5 + as-found/readback/ExecStart 0.5 + near_on/unmute 0.5 + legs 3-6 ~7 (engine ~0.5, T1/T2/T4 ~2 each) + put-back ~1.5 | **~41 min**: legs at caps (engine wait 120 s; each task quiet 90 + new work 60 + done 420 s ≈ 9.5 min × 3) + put-back ~4 |
| Piece B | **~16 min**: lock/check/ready/near/unmute ~1 + legs ~8.5 (first-on 0.5, engine 1, MAKE ~3, TRY ~1.5, RUN ~1.5, REMOVE 0.75, put-back ~1) + r2→release ~5.5 + near_off/engine file 0.5 | **~40 min**: MAKE_WAIT 480 s + quiet 90 (~10 min), TRY and RUN RUN_WAIT 360 + quiet 90 (~7.8 min each), REMOVE ~2, two engine waits of 120 s, + ~8 fixed |

Waits outside these numbers:
- `other_quiet` waits up to 900 s per clip while another team posts `PLAYING` on #7875.
- The 10-starts-in-10-min gate waits in steps of 60 s. Starting B straight after A can hold B's first restarts for a few minutes, because A's last 10 min hold about 4 starts.

Both worst cases are over 20 min. **No wait is cut in the kit.** To bring the worst cases down:
- `quiet` 90 → 20 s. This is not a PASS condition: it only logs a note and plays anyway.
- `other_quiet` 900 → 60 s. This makes it a STOP, not a PASS change.

Those two alone give A ~37 and B ~35. Reaching 20 min means cutting PASS windows:
- **A**: each task's done-within cap, 420 → ~90 s (literal 420 in `legs8156.zsh` `task`/`follow`).
- **B**: `MAKE_WAIT` 480 → 240 and `RUN_WAIT` 360 → 150 (both env vars), plus the 120 s kept-session wait (`WAIT_S` in `lamp.sh`, a PASS window of READY/ENGINE) → 60. That gives B about 21 min.

Shortening a PASS window this much would fail slow but correct runs. The recommendation is to keep the caps, budget the slot on the typical times, and accept that a worst-case piece overruns.
