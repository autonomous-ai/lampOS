# #8337 ROW on lamp-ee17

#8337 changes lamp-update's agents list: an engine Harness reads as `installed: null` with `installable: true` is no
longer said `not_installed` (#8286). Since it changes lamp-update, its ROW comes from a **real update round** of the
lamp's own lamp-update, from stable to the CI build of the head, never a hand install (First's rule of 19 Nov). A
second real round puts stable's bytes back at a higher sequence.

This kit is the #8162 kit (`kits/8162-e82d`) with its voice legs, the mute and Harness's step-down left out: #8337
pins Harness 0.6.75, as stable does, and plays nothing. It adds leg E: the agents list the app is shown.

## The rounds
Channel mode, as the #8138 and #8162 kits: `CH1` (the PR build, every non-development binary of the CI artifact, units
and skills from the artifact's own tree, sequence `ROUND1_SEQ`) and `CH2` (stable's signed manifest bytes with only
`sequence` changed to `ROUND2_SEQ`), both signed with a throwaway test key on the Mac (never on the lamp), and
`TEST_PUB`. The kit copies them to the lamp and points lamp-update's own product line at them by /run drop-ins, which
`putback` removes. `ROUND1_SEQ` must be above the highest sequence the lamp has seen; `ROUND2_SEQ` above `ROUND1_SEQ`.

## Steps
`KIT_ENV=<env> CH1=... CH2=... TEST_PUB=... ROUND1_SEQ=... ROUND2_SEQ=... STABLE_SEQ=... STABLE_UPD_SHA=... ./run.sh`

| step | what it does | ~min | go on at |
|------|--------------|------|----------|
| lock | lamp-lock try, then a 60 s renew loop | 0 | `LOCK TAKEN` |
| base | read only: on stable (or above it with stable's updater), its product line, nothing staged, Harness 0.6.75, OpenClaw the default agent, the units' running exes recorded, the speaker read (over 40% or unread stops; never set) | 1 | `BASE OK` |
| engines0 | read only: the list the app is shown on stable (`update/status`'s `engines`) | 0 | `ENGINES0 {` |
| round1 | round 1 to the PR build; lamp-update's own end (`up to date: build ROUND1_SEQ` after its self-switch) | 3-15 | `ROUND 1 OK` |
| verify | every 30 s, up to 15 min: build ROUND1_SEQ, the PR's updater, Harness 0.6.75, nothing newly failed, tasks/agent ready with OpenClaw | 1-15 | `VERIFY PASS` |
| engines | leg E (below): waits up to `ENGWAIT` (420 s) for lamp-update's first Harness look since round 1, then reads the list | 1-7 | `LEG E ...` |
| round2 | round 2 to stable's bytes at ROUND2_SEQ; stable's updater running again | 3-15 | `ROUND 2 OK` |
| putback | no stopped pid left; the drop-ins removed; the product line's own round | 1-2 | `PUTBACK OK` |
| read | two reads 60 s apart: as base found it, the same exes | 2 | `READ TWICE same` |
| release | the lock, only after PUTBACK OK and READ TWICE same (`FORCE=1` releases anyway) | 0 | `LOCK RELEASED` |

About 30-45 min. The runner is a light shell on the Mac: ssh, journal reads, one copy of about 300 MB.

## Leg E, the agents list the app is shown
Read from lamp-update's kept `update/status` on the bus (`/run/lampos-bus/update/status/latest`), as lamp-cloud
gives the app `update.status` (docs/cloud.md, "The lamp's agents"). Also lamp-update's last word on its Harness look
since round 1 (`engines.rs`: "the lamp's Harness said its engines", or "... did not say its engines, the last kept:
<why>").
- `(E0)` the list on stable, `(E1)` on the PR build, `(E2)` the Harness look's line.
- `(E3)` Hermes and OpenClaw are listed with the states stable said, and no engine stable said `installed` is now
  `not_installed` (#8286's harm).
- `(E4)` Harness's own engines listed, with whether its look answered.
- **PASS:** E3 holds and, when the look answered, at least one engine of Harness's is listed. When the look did not
  answer (Harness signed out, say), PASS says so: Harness's engines keep the last look, so #8286's `null` rows are not
  reached on that lamp; the unit test `an_engine_harness_does_not_say_is_installed_is_never_said_not_installed` covers
  them. **FAIL:** E3 broken, or the look answered with no engine listed. **VOID:** the PR build's list not read.

A FAIL or VOID never stops the run: round 2, the put-back and the reads still run.

## Mocks
`mock/row/run-all.sh` runs 23 cases with stub ssh, scp and lock and recorded lamp outputs: the RUN cases kept from
the #8162 kit (lock, volume, speaker, sequences, rounds never ending or refused, round 2's updater, the reads) and leg
E's own (PASS signed out and signed in, an installed engine said not installed, OpenClaw moved, a look that answered
with nothing listed, the list unread). Each of leg E's three FAIL rules was broken by hand once, and its case then
gave PASS (a MISMATCH): the cases catch them.

## Safety
The lamp's speaker is only read. lamp-cloud is never stopped. No factory reset, no forget-all. GATE keeps each unit at
10 starts or fewer in any 10 min. Credentials come only from `KIT_ENV`; the sudo password goes only to sudo's stdin.
The test key never leaves the Mac; only its public half goes to the lamp, in /run and the staged channel folder.
