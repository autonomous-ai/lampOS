# #7901 ROW on any lamp

#7901's scope: a made skill may hold `net` beside the camera, notes and every other grant. The net-beside-private
refusal is gone everywhere. These still hold: admin.sock (and all of `skill_run::HIDDEN`) stays hidden from a run,
keys stay refused, the per-run cgroup stays, and NotTried fails closed.

This kit runs the legs from the runner's Mac. It has not run on a lamp yet. It has only been mocked:
`mock/run-all.sh` runs 79 cases, all with stub ssh, scp, afplay, push and lock: every leg's PASS, FAIL and VOID cases (the
make legs both with and without a yes), `run.sh` end to end, and 17 helper cases (`mock/unit.sh`: the engine read, the mute check, the ssh retry, the Mac
volume read, `mock/fixcheck.py` on legs S and K's pushed fixtures against the loader's rules, and `push-k`: K's fixture
in by the product's push install and out by unrow's `remove_pushed`, against a fake manage helper). With K put back on
`push.py`, `K.pass`, `K.fail-token`, `U.push-k` and both `RUN.pass` cases come out wrong.

The runner is Migrate, on lamp e82d, with #7901's build put on by a real round (Prerequisite 1).

#7901 now sits on #8180's head f45ad0f9ec. #7901's own head moves with it, so the kit never names a head: the build
it checks is the one whose sha256s you give in `PR_*_SHA`.

## Prerequisites
1. **Round 1 (yours, before the kit).** Put #7901's CI ARM64 artifact on the lamp by a real round from a test
   channel: sign it with a throwaway key, swap that key's `key.pub` in, add a /run drop-in on lamp-update that
   changes only `--channel-url`, and publish a sequence above stable's. Note the artifact's sha256 for lamp-voice,
   lamp-skills, lamp-control and lamp-tasks.
2. The lamp's default agent is OpenClaw, lamp-cloud is active, LAMP_TASK_NET, LAMP_TASK_NET_GATEWAY,
   LAMP_SKILL_TASKS and LAMP_MADE_SCRIPTS are on (the product's), and the physical mic slide is open.
3. The env file (`KIT_ENV=<path>`) is sourced, never copied or printed:
   ```
   LAMP=<lamp name>            # for the lock and the logs
   LAMP_HOST=<address>
   LAMP_USER=<ssh user>
   LAMP_SUDO_PASS=<sudo password>
   LAMP_SSH_PASS=<ssh password> # optional (sshpass -e); leave it out to use ssh keys
   LOCK_WHO=<lock holder>       # required with KIT_LL; LOCK_SESSION defaults to row-7901
   KIT_LL=<path>/lamp-lock.sh   # optional; with none, no lock is taken or renewed
   PR_VOICE_SHA=  PR_SKILLS_SHA=  PR_CONTROL_SHA=  PR_TASKS_SHA=   # the artifact's sha256s (strongly advised)
   ```
4. On the Mac you need bash, python3, ffmpeg, ffprobe, afplay and osascript, plus sshpass if you use
   LAMP_SSH_PASS. For leg S: the lampos SDK in that python3 (`pip install lampOS/sdk/python`), and the Mac
   paired with the lamp with the `skills` and `speak` grants (`lamp pair CODE --pin PIN --host <address>`, the code
   and pin from the owner's app, once, before the kit). `LAMP_PAIRED=<name>` in the env file picks a pairing when the
   Mac has more than one. With no pairing, S is VOID (`the install route is unavailable`). Leg K needs
   no pairing and no pip: its fixture goes in by the product's push install (see K below), packed with this worktree's
   own `lampOS/sdk/python/src` (`PUSH_SDK=<folder>` points elsewhere). The Mac's output volume must be 70 or lower. The kit only reads it and never sets any volume.
   It plays clips with `afplay -v` gain only. Put the Mac's speaker next to the lamp.

## Commands (from `kits/7901/`)
`KIT_ENV=<env> MIC_YES=yes ./run.sh` runs every step in order. To resume, name a step: `./run.sh <step>`.
`./run.sh <step> <then>` runs one step, then goes on at `<then>`. `UNTIL=<step>` stops before that step.

| step | what it does | ~min | go on at |
|------|--------------|------|----------|
| lock | lamp-lock try, then a renew loop every 60 s (only with KIT_LL) | 0 | `LOCK TAKEN` or `LOCK none` |
| render | renders the 10 clips (row/clips/clips.txt) through the lamp's own ElevenLabs relay, with ffmpeg on the Mac | 2 | `RENDER OK` or `RENDER nothing to do` |
| check | each part's running exe and installed file sha256 against `PR_*_SHA` (printed when not set), the gateway's lamp-skills, switches, engine, ready | 1 | `VERIFY PASS`, `READY` |
| notes | LAMP_MADE_NOTES=on in lamp-voice and lamp-control by /run drop-ins (1 start each) | 1 | `NOTES ON OK` |
| micon | records the mute and lifts it, only with MIC_YES=yes (the lamp's person's yes for this ROW) | 1 | `MUTE LIFTED OK` or `MUTE NOT MUTED` |
| save | the mute is off, then the baselines (made.json, skills, notes files) | 1 | `MUTE OFF OK`, `SAVED OK` |
| legs | `row/row.sh A B C D S K` | 38-45 | `VERDICT PASS` |
| unrow | takes S's pushed fixture off by the Mac's pairing (`row/push.py remove`) and K's by the manage helper's `remove_pushed` (`task-yes.json` back as found), then removes the notes drop-ins, the row's skills, made.json entries and notes files | 1 | `UNROW OK` |
| micoff | puts the recorded mute back | 1 | `MUTE BACK OK` |
| release | releases the lock (needs UNROW OK and MUTE BACK OK) | 0 | `LOCK RELEASED` |

The kit takes about 50-55 min. A make leg (A, C) can take up to 11 min. **Round 2 (yours, after `UNROW OK`):** a
second round back to stable's bytes, and remove your channel drop-in and key.

Rules the kit keeps:
- The engine is the app's choice (`/var/lib/lampos-tasks/store/engine-default.json`) when there is one. With none,
  it is `LAMP_LAMP_ENGINE` in lamp-tasks' environment, then lamp-voice's. `check` and `save` need it to be openclaw.
- The mute check (`save`) reads the live `voice/mute` value first. Only when that is unread does it use
  `record.json`'s `muted`. `through_us` is the record's last-change stamp, not an end time, so it never turns a
  muted record off.
- An ssh call is tried again (at most 3 tries, 2 s apart) only when the lamp refused the login: ssh exit 255, or
  sshpass exit 5, with `Permission denied` in its stderr. Any other failure stops at once. The journal follow is
  never retried.
- It never sets any volume and never stops lamp-cloud.
- GATE refuses a unit start when that unit already has 9 or more starts in the last 10 min.
- On ANY exit, the EXIT trap puts the recorded mute back, once. It keeps the lock, and says so if the notes
  drop-ins are still on.

## A make, with or without a yes (#8180)
#8180's `LAMP_MADE_CODE_ON_AT_ONCE` is on in the product's lamp-voice and lamp-control. With it, a made skill with
code of its own that is not a task for the lamp's agent goes on at once: no read-back and no yes. The voice says
"Made it. It uses ..., and I tried it: <the try's first words>. Say 'remove it' to undo." The kit handles both paths
and logs which one it saw in row/logs/paths.txt (`PATH A at-once`, `PATH C yes`):
- **at-once**: the journal shows `is on at once (LAMP_MADE_CODE_ON_AT_ONCE); its task kept`. YES is not played. The
  skill must be on the lamp, and its task kept.
- **yes**: there is a read-back line (the switch is off, or the make is an agent task). YES is played, as before.
- With neither line, YES is played, as before (`PATH none`).
Legs A (A5) and C (C5) check the try. When a try ran (`[lamp-tasks] make try`), it must end with exit 0 and
`said` of 1 or more: lamp-control answers the try's say at once (f45ad0f9ec). On the at-once path, the tried line
must also follow, naming what the skill uses. The product journals only that line's length
(`a made skill is said on with its try (N chars, uses named)`), never its words. Whether the line starts "Made it"
and then says the try's first words can only be heard in the room.

## On a STOP
- `STOP at check`: the lamp is not on #7901's build, or it is not ready. Read row/logs/check.txt, fix your round, then
  `./run.sh check`.
- `STOP at notes`, `unrow` or `micoff: start budget`: wait 10 min, then run that step again.
- `STOP at micon`: MIC_YES is missing, or the physical slide is closed, which needs a hand. Nothing was lifted.
- `STOP at save` (or any later STOP): the trap has put the mute back. Fix the cause, then `./run.sh micon save`.
- A leg FAIL or VOID never blocks the put-back. To redo one leg: `./run.sh micon legs` with `LEGS="D"`, for
  example. If D says `RUNC ran another skill`, set the RUNC line in row/clips/clips.txt to name C's skill
  (row/logs/skill-c.name), then run `./run.sh render`, then the leg again.
- `WARN ... mute NOT back`: `./run.sh micoff`. Keep the lock until you read `UNROW OK` and `MUTE BACK OK`.
- `LOCK: not ours`: stop, and run no ssh.

## Optional path (not the ROW's way in)
`optional/swap.sh` and `optional/restore.sh` bind the artifact's four binaries over the installed ones, for a lamp
where no test-channel round can be made. A swap does not exercise the update path. Order: `./run.sh lock`, then
`optional/swap.sh`, then `UNTIL=micoff ./run.sh check` (it runs through unrow), then `optional/restore.sh`, then
`./run.sh micoff release`.
